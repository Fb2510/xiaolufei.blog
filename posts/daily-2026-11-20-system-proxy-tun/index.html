系统代理和 TUN 模式怎么选？哪些情况值得打开 TUN

小路带你飞2026-11-20— 次阅读
机场与VPN

浏览器和常用软件已经能正常使用时，可以继续用系统代理，不必为了“功能更全”打开 TUN。如果浏览器正常，某个软件却一直连不上，先检查它是否采用系统代理；对于不采用这项设置的软件，TUN 才是值得进一步了解的选择。

下面以 Windows 上的 Clash Verge Rev 为例，其他客户端的开关、权限和默认配置可能不同。

两个开关分别做什么

系统代理像是在系统里留下一个接待地址，愿意使用它的软件，会把网络连接交给代理程序；也有软件不读这份设置。

TUN 则通过虚拟网卡，也就是软件建立的网络接口，接收按系统路线送来的连接，再交给代理程序处理。它不要求每个应用主动读取系统代理地址。项目的名词解释说明了这两种接收连接的方式。

因此，看到系统代理开关亮着，只能确认这项设置已开启，不能据此认定每个程序都在走代理。

哪些情况可以考虑 TUN

官方入门教程将系统代理用于常见的浏览器访问需求，并把 TUN 作为接管不支持系统代理程序的一种方式，举例包括部分游戏和命令行工具。命令行工具就是通过输入文字命令运行的软件。

假设你能在网页里查看一个资料包，但独立下载软件始终连接失败。这时可以先查看下载软件有没有自己的代理选项，或能否跟随系统设置。若它本来就支持正确的代理配置，先处理那里；若没有合适入口，再按照客户端教程尝试 TUN。

这个场景只是说明检查思路，不代表下载失败一定由代理方式造成。目标服务器故障、账号限制等问题，也不会因为打开 TUN 就自动消失。

打开 TUN，不等于所有连接都走同一个节点

TUN 负责把连接交进来，收到后怎样出去仍要看客户端配置。规则模式会按配置分配路线，全局模式则使用相应的出口选择；这与接收连接的方式是两回事。路由模式说明

另外，TUN 可以设置排除范围，让部分连接不进入它。官方绕过说明列出了这类配置。因此，开关开启后仍要确认目标软件的实际表现，不能把它当作全设备必走代理的证明。

按四步尝试，方便恢复

  1. 先留下原样。 记录系统代理、TUN 的开关状态，以及当前节点和规则模式，保存正在进行的下载或编辑任务。
  2. 确认启动条件。 阅读对应版本的 TUN 教程。Clash Verge Rev 的服务模式用于让普通权限启动的界面也能使用 TUN；它需要先完成相应的服务安装和授权。不要把“服务未启动”当成节点故障。服务模式说明
  3. 只改变接收方式。 按教程启用 TUN，尽量保持节点、网络和规则不变，重新打开原先失败的软件，测试同一个功能。
  4. 记录结果并复查。 除目标软件外，再试常用网页和本地设备连接。若出现新的异常，先恢复之前记录的开关状态，保留具体错误信息。

项目的 Windows 常见问题提到，多张网卡或网段与规则冲突，可能导致 TUN 开启后网络异常。mihomo 的 TUN 文档也单独说明了出口网卡选择。

新手遇到这类情况，先把系统版本、客户端版本、原始设置和失败操作整理出来再求助，不要直接删除自己不认识的网卡。能说明“同一节点下，开启前后哪个功能发生变化”，比一句“TUN 没用”更容易找到原因。
